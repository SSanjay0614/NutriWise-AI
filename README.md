# NutriWise AI — Diabetes Diet Assistant

**Explainable, rule-based diet guidance and personalized meal planning for people managing diabetes.**

> ⚠️ **Educational prototype — not a medical device.** NutriWise provides *dietary information only*. It does **not** diagnose, treat, or dose medication, and it **never** advises on insulin. Always follow your doctor's and dietitian's guidance.

---

## What it does

1. **Builds a profile** on first run (age, gender, weight, height, activity, diabetes type, insulin use, optional HbA1c and conditions).
2. **Derives personalized daily nutrient goals** from that profile — a calorie target, a **carbohydrate budget**, a sugar ceiling, a fiber minimum, protein/fat targets, and a sodium ceiling.
3. **Logs one fasting blood-glucose reading per day** (mg/dL). The reading is categorized and used to tighten the day's carb budget when it is elevated or high.
4. **Logs meals** — searched from the NutriWise dataset (each food carrying a **glycemic index (GI)** and a **diabetes rating** of good / moderate / limit), or any food not in the dataset is estimated by the LLM so it can still be logged.
5. **Assesses** the day's intake against the personal goals and today's glucose.
6. **Recommends** diabetes-aware next-meal priorities (low-GI, high-fiber, carb-controlled).
7. **Generates a full-day meal plan** sized to the carb budget using low-GI foods.

---

## The blood-sugar input

The daily input is a **fasting blood glucose (blood sugar)** value in **mg/dL** — not insulin.

| Fasting reading | Category | Effect on the day |
|---|---|---|
| < 100 mg/dL | normal | carb budget unchanged (×1.0) |
| 100–125 mg/dL | elevated | carb budget ×0.9, low-GI emphasis |
| ≥ 126 mg/dL | high | carb budget ×0.8, strong low-GI + low-sugar steer |

(An optional post-meal reading uses 140 / 180 mg/dL thresholds.)

---

## How goals are derived

- **Calories:** Mifflin-St Jeor BMR × activity multiplier (TDEE). Trimmed ~10% for overweight Type 2 / prediabetes users to support gradual weight management.
- **Macros:** ~45% carbohydrate, ~20% protein (≥ 1 g/kg body weight), ~35% fat.
- **Fiber:** ~14 g per 1000 kcal, minimum 25 g.
- **Sugar:** ≤ 25 g/day ceiling.
- **Sodium:** ≤ 2300 mg, tightened to ≤ 1500 mg for hypertension/kidney concerns.

All values are educational estimates, not prescriptions.

## Food dataset

`data/nutriwise_foods.csv` — 150 prepared Indian dishes, fast foods, staples, fruits, and drinks. The diabetes pivot added two columns:

- `glycemic_index` — approximate GI (0–100), compiled from published references and category reasoning (**estimates**, generated by `scripts/prepare_diabetes_data.py`).
- `gi_category` — `low` (≤ 55) / `medium` (56–69) / `high` (≥ 70).
- Micronutrients (`vitamin_a/c/d/b12`, `folate`, `magnesium`, `zinc`) — approximate estimates added by `scripts/prepare_micros.py`.

Each food's **diabetes rating** (good / moderate / limit) is computed at runtime from GI + per-serving sugar, fiber, and carbohydrate load (`nutrition/diabetes_score.py`).

## Architecture

```text
User profile ──► GoalCalculator ──► personalized NutrientGoals
                                            │
Daily fasting glucose ──► GlucoseMonitor ───┤ (adjusts carb budget)
Logged activity ──► ActivityEstimator ──────┤ (raises calorie/carb budget)
                                            ▼
Meal food ─► NutriWise dataset lookup ─► NutritionCalculator (deterministic)
   (or LLM estimate if not in dataset)   (GI + diabetes rating)
                                            ▼
                               Supabase (per-user: profile, glucose, meals, activity)
                                            ▼
         NutritionAssessment ◄── goals + glucose ──► MealRecommender
                                            ▼
                     DiabetesMealPlanner · weekly analysis · food exchange
```

Foods missing from the dataset fall back to a Gemini structured estimate, tagged as an estimate with an approximate GI.

## Setup & running

NutriWise is a full-stack web app: **FastAPI** backend + **React (Vite)** frontend,
with **Supabase** (cloud Postgres + auth) for per-user data, and an **LLM**
(Google Gemini) for foods outside the dataset and the
analysis summary.

See **[docs/WEB_SETUP.md](docs/WEB_SETUP.md)** for the full one-time setup
(create a Supabase project, fill `.env`, run the SQL in `supabase/`). In short:

```powershell
conda activate conda_env
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
python -m backend.seed_demo          # optional demo account
uvicorn backend.main:app --port 8000 # open http://localhost:8000
```

`.env` holds the Supabase keys and `GEMINI_API_KEY` / `GEMINI_MODEL`
(see `.env.example`). The food dataset is already prepared; to regenerate its
estimated columns, run `python scripts/prepare_diabetes_data.py` and
`python scripts/prepare_micros.py` from the project root.

## Key modules

| Module | Responsibility |
|---|---|
| `backend/main.py` | API routes; serves the built frontend |
| `backend/auth.py`, `backend/db.py` | Supabase auth + per-user data |
| `nutrition/goals.py` | BMR/TDEE → personalized `NutrientGoals` |

| `nutrition/calculator.py` | Deterministic serving-size nutrition math |
| `nutrition/assessment.py` | Intake vs goals + glucose assessment |

| `nutrition/meal_planner.py` | Full-day carb-budgeted meal plan |

| `nutrition/analysis.py` | Weekly stats, insights, coach summary |

## Limitations

- GI, micronutrient values, and goal formulas are **approximate educational estimates**, not clinically validated.
- Localhost prototype; not hardened for public deployment.
- Off-dataset foods and the AI analysis summary depend on an LLM being configured.
- No medication, insulin-dosing, or treatment guidance — by design.

---

## Disclaimer

NutriWise is an educational prototype. It is **not** a substitute for professional medical or dietary advice, diagnosis, or treatment. People with diabetes should make medication and insulin decisions only with their healthcare team.
